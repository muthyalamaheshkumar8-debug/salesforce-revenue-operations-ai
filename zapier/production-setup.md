# Zapier native run setup
The included backend receiver is executable; a Zap has not been created or run here.

1. Deploy the FastAPI backend privately over HTTPS with a durable `WORKFLOW_STATE_PATH` volume.
2. Set `ANALYSIS_API_TOKEN`, `WORKFLOW_CURRENCY` and `HIGH_VALUE_THRESHOLD` privately. Do not copy these values into source or the public dashboard.
3. In your Zapier account, create a Zap. Choose the Salesforce Opportunity update trigger, or Webhooks by Zapier → Catch Hook. For Catch Hook, submit only an authorized test opportunity to the URL generated by Zapier. Do not treat this document as a live trigger URL.
4. Add Webhooks by Zapier → Custom Request: POST your backend `/api/operations/webhooks/zapier`, JSON body `{ "event_id": "<stable ID>", "opportunity": { "Id": "<Salesforce ID>", "StageName": "Negotiation", "Amount": 600000, "CurrencyIsoCode": "INR", "LastModifiedDate": "<source timestamp>" } }`. Set `Content-Type: application/json` and `Authorization: Bearer <private analysis token>` using private credential fields.
5. Test once. Retry with the same ID/body: expect `duplicate`. Change the amount with the same event ID: expect rejection. Currency mismatch: rejection. Below threshold: `below_threshold`.
6. Keep the Zap run ID, run time, input field mapping and response privately. The stored outbox awaits human review; there is no email/Slack action in this project.

Native Zapier setup/testing can depend on your plan and app permissions. No paid account or purchase was initiated. Do not claim Zapier experience until you have actually configured and run the Zap.
Official documentation: https://help.zapier.com/hc/en-us/articles/8496288690317-Trigger-Zap-workflows-from-webhooks and https://help.zapier.com/hc/en-us/articles/8496326446989-Send-webhooks-in-Zap-workflows . Checked 2026-10-08.
